# build/beastnet: the beast-net helper environment

Builds the files of `docs/BEASTNET.md` §3 that come from the build:

```
bash build/beastnet/build.sh OUT_DIR
  OUT_DIR/beast-net/vmlinuz          Ubuntu's Canonical-signed kernel, byte-identical to the .deb
  OUT_DIR/beast-net/initrd.img       xz newc cpio (§5)
  OUT_DIR/beast-net/VERSION          "beast-net <VERSION> kernel <kver>"
  OUT_DIR/beast-net/catalog.json     firmware pack catalog (§6)
  OUT_DIR/beast-net.origins.json     {"beast-net/<file>": "<origin>"} for dist/manifest.json
  OUT_DIR/beast-net.contents.json    every file inside initrd.img (origin, SHA-256), the
                                     packages, the module list, the firmware report
```

Rootless, idempotent (a second run is byte-identical), offline once the caches
are warm (`BB_OFFLINE=1` enforces it). Caches: `.tools/cache/beastnet/debs/`
and `.tools/cache/linux-firmware/<tag>/`.

## Inputs

| File | What |
|---|---|
| `packages.in` | top-level Ubuntu packages and versions (edit this) |
| `packages.lock` | every .deb with exact version + SHA-256 (generated by `lock.py`, never edited) |
| `userland.list` | which files of each package go into the initramfs |
| `modules.list` | the kernel module subset (closure via modules.dep/softdep/weakdep) |
| `firmware.lock` | linux-firmware tag + commit for the catalog |
| `../../beastnet/` | the app: `rootfs/` copied verbatim, `python/beastnet/` to `/usr/lib/python3/dist-packages/beastnet/`, optional `runtime.json` |

`runtime.json` (optional, from the app): `{"binaries": [...]}` must be shipped
(names are looked up in /usr/bin and /usr/sbin), `{"python_modules": [...]}`
must import with the shipped Python (checked at build time),
`{"files": [...]}` absolute paths that must be shipped (taken from any locked
package if `userland.list` does not include them).

## How it is put together

- **Kernel**: `/boot/vmlinuz-<kver>` from `linux-image-<kver>`, checked against
  the package md5sums, `sbverify --list` (Canonical Ltd. Secure Boot Signing,
  issued by the Canonical Master CA), `sbverify --cert` with the vendor
  certificate embedded in the shim we ship (`$BB_SHIM_DIR`), and shim-signed's
  `is-not-revoked`.
- **Modules**: the `.ko.zst` files of `linux-modules-<kver>`, unmodified;
  `depmod` (the locked kmod, run with the locked glibc) on the full tree to get
  the closure, then on the subset. Every module must carry a signature, all
  from the same key (the kernel's built-in build key).
- **Userland**: files picked by `userland.list`; every `DT_NEEDED` library of
  every shipped ELF file is resolved against the locked library packages and
  exactly those files are added. Layout: merged `/usr` (`/bin`, `/sbin`,
  `/lib64` are links) except `/lib`, which is a real directory holding
  `firmware/` and `modules -> ../usr/lib/modules`, because a firmware pack
  cpio contains a `lib` directory entry and the kernel's initramfs unpacker
  replaces an existing entry of another type (a `/lib` symlink would be deleted).
- **Generated**: busybox applet links (for names no package ships), `python3 ->
  python3.14`, `/etc/ssl/certs/ca-certificates.crt` (all certificates of
  `ca-certificates`, concatenated in file name order as `update-ca-certificates`
  does), OpenSSL's default `cert.pem` link, minimal `/etc` files (the app's
  `rootfs/` may replace them), `/dev/console`, depmod output.
- **Checks at build time**: the shipped Python imports ssl, hashlib, curses,
  json, urllib, ... (plus `runtime.json`), loads the CA bundle, finds terminfo
  for linux/vt100/xterm, and finds the `beastnet` package; every symlink
  resolves inside the initramfs; no locked package is unused.
- **cpio**: sorted, uid/gid 0, mtime `SOURCE_DATE_EPOCH`, inodes 1..n, dirs
  0755, files 0644/0755; xz with CRC32 and LZMA2 only (what the kernel's
  decompressor supports).

## Firmware catalog (`gen_catalog.py`)

Firmware names come from `modinfo` of the bundled modules of each pack,
resolved against linux-firmware at the pinned tag: exact names, WHENCE `Link:`
names, globs, iwlwifi/ath10k API numbers (the highest version the driver can
load), iwlwifi stepping variants and PNVM files, plus the LICENCE files the
WHENCE licence lines name. The tree listing comes from a blob-less git fetch
of the GitLab mirror (the tag must be the pinned commit there and on
git.kernel.org); each file is downloaded as a git object from GitLab (git
checks its id) and again from its kernel.org `plain/` URL, and both must be
identical. `BB_BEASTNET_REVERIFY=1` re-downloads every catalog file from
kernel.org. `beast-net.contents.json` lists requested names that linux-firmware
does not have, and bundled modules that need firmware but belong to no pack.

**Catalog extension**: a file installed under a WHENCE link name has
`"source_path"`, the path in the repository to download (`url_template` with
`{path}` = `source_path`); without it, `path` is both. All iwlwifi files are
such links (`iwlwifi-*.ucode -> intel/iwlwifi/...`).

## Notes for the app

- busybox is Ubuntu's dynamically linked `busybox` package (it uses the
  locked libc6; `busybox-static` embeds its own glibc copy, which the SBOM
  then reports with that glibc's CVEs). It is built without
  `FEATURE_SH_STANDALONE`, so busybox sh, `xargs` and `mdev` find programs
  through `$PATH`: a bare `modprobe` is kmod's (`/usr/sbin/modprobe` from the
  kmod package wins over an applet link, which is only made for names no
  package ships). Calling `/usr/sbin/modprobe` by full path stays the safe
  habit; kmod is the tool that matches depmod's output (softdeps such as
  r8169 -> realtek PHY, weakdeps, modprobe.d).
- No udhcpc default script is shipped (the busybox package has none); pass `-s`.

## Updating

- New Ubuntu package versions: edit `packages.in`, run `python3 -I build/beastnet/lock.py`
  (`--check` tells whether `packages.lock` is current), rebuild.
- A package from another Ubuntu series: add `suite=<series>` to its `packages.in` line (the
  kernel uses `suite=stonking`, Ubuntu 26.10). lock.py then uses a private apt configuration
  with only that series' release, -updates and -security pockets (never -proposed), checked
  with the Ubuntu archive keyring, and writes the series' purl distro (`ubuntu-26.10`, from its
  signed InRelease) as a 6th column of `packages.lock`; the SBOM uses it for the kernel and
  modules packages. The build fetches such a .deb from Launchpad by its locked SHA-256.
- New kernel: also update `modules.list` if a pattern stops matching (the build says which).
- New linux-firmware tag: edit `firmware.lock` (tag + commit), rebuild with network.

## Test

```
source scripts/dev-env.sh
python3 -I build/beastnet/test/qemu_test.py OUT_DIR [--inet URL] [--app]
```

Boots the kernel directly in QEMU (KVM, serial console, `module.sig_enforce=1`)
with a copy of `initrd.img` plus a test overlay (`test/test-init` as `/init`)
and a firmware-pack-format cpio, three NICs (e1000, e1000e, virtio-net), two
USB disks (exFAT on usb-storage, FAT32 on UAS) and a host HTTPS server with a
throwaway CA. It checks module autoload, DHCP, TLS (the shipped bundle rejects
the throwaway CA, a test-only copy with it accepts, wrong host names fail),
curses, mac80211_hwsim + a WPA2 association between two wpa_supplicants (AP and
station), exFAT/FAT32 mount and write, pack layering, and that nothing taints
the kernel. `--app` also boots the real `/init` with `beastnet.debug=1`.
